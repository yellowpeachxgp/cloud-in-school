# 独立修复复核（2026-11-15）

本轮以 PR #2 的 `bb95252c34e23088f83aafcc8e18d977e84788ae` 为起点；fetch 与 GitHub PR head 一致，初始工作区干净。没有生产调用、生产迁移、真实预约、扣款或退款。

## 已证实的问题与入口

- `apps/api/src/app.mjs` 的 `createReservationPlan` 曾直接重放内存回执，即使先前 rename 后目录同步仍失败。失败回归收到 200，期望 503。
- `packages/db/src/index.mjs` 曾只校验文件大小，未保存报价集合，并截断回执；报价消费无法跨重启完整恢复，回执也不能永久防重复。
- `apps/api/src/shutdown.mjs` 曾依据任务计数与 close 回调计算结果，忽略同步 flush 已超出绝对预算。回归得到 `deadlineExceeded=false` 与成功退出。
- 实际 main 子进程测试发现强制断开未读完请求会导致未处理的 `ECONNRESET`，缺少最终关闭日志。
- 复查同根因：PATCH 预约只异步保存；真实资金旧在途操作可能再次 POST。另复核在途状态 CAS、续期、退座逐次派发及扫描器错误路径，隔离期间保留待执行事件，不能误标业务失败。均补回归并修复，未知资金仅回查，不能自动重发真实扣退款。

## 快照协议与恢复

本实现只支持**同一快照路径的单进程单写者**，没有租约或 fencing，不支持多副本共同写、共享 NFS 写入或滚动双写。运行时要求文件系统支持文件和目录 fsync；不支持目录 fsync 的错误不再被当成成功。

1. 整个候选单元含 plan/job/event、替换旧计划状态、报价消费、幂等回执、资金与 outbox。已签发报价先严格保存；消费时与其余对象一起提交。临时文件以 0600 独占创建，写入并同步。
2. `.intent` 先记录旧/新快照 SHA-256，文件及目录同步后才 rename。新建存储目录也同步父目录项。
3. rename 后同步目录、读取完整内容校验摘要、清理 intent 并再次同步目录，才确认耐久成功。
4. rename 前确定失败：创建和 PATCH 可恢复内存原状态。rename 后失败：保留候选状态，返回 `503 STORAGE_COMMIT_UNKNOWN`，隔离 HTTP、扫描器、资金入口及后续快照覆盖。回执不是耐久性证明。
5. 同进程重试先校验磁盘与候选摘要、回执到计划/任务/事件的引用，重新同步文件和目录；失败仍 503。成功后同键同 payload 重放原始冻结结果；不同 payload 返回 409。字段顺序变化通过规范化 hash 处理，同时保留旧 hash 兼容旧回执。
6. 启动时在加载和恢复任务之前执行相同核验。若可见快照匹配新摘要，恢复候选；若仅匹配旧摘要，恢复完整旧快照，原键重试可以安全完成此前未发布的请求；不匹配则拒绝启动。未发布临时文件不自动提升为已提交。

客户端收到未知结果必须保留**原键及原请求**，不能换键、自动重建、恢复另一引擎并跑或认定资金已成功。旧无键客户端应查询计划并人工核对，不能盲目重做。耐久隔离期间读端点也返回 503，避免把候选状态展示成确定结果。

补查学校适配器发现区域/座位接口也会把未来日期换成今天，返回后却标成目标日期，并伪造全部空闲。已与 Day 同时取消这些回退和可用状态覆盖，真实请求使用目标绝对日期。学校未开放该日期查询时明确失败；执行入口即使收到旧的跨日回退选项也只使用计划日期。真实学校对未来查询的兼容性未验收，不能以其他日期布局代替目标日期的可用证明。

## 停机和进程边界

main 先停后台入口、设置 draining、停止监听，再在同一单调时钟 deadline 内排空注册任务、严格保存、确认 server close。最终 `elapsedMs`、`deadlineExceeded`、`tasksDrained`、`drained` 和退出码一起计算；超时或未完整关闭退出 3，只有全部成功且未超时才退出 0。

同步 I/O 不能被同线程 timer 中断。默认 `npm start` 和容器通过独立 `apps/api/src/supervisor.mjs` 启动 main：软预算 15 秒、外部硬预算 20 秒；硬超时独立记录 `drained=false` 并 SIGKILL 子进程，退出 137。Compose 配置 25 秒 stop grace 和 init 作为更外层兜底。直接运行 main 时须另配外部 supervisor，不能宣称 main 自身有硬中断能力。

## 验证范围

- 先运行失败回归，再修复；专项覆盖目录同步持续失败、内容篡改、回执同/异 payload、并发不同键、发布前阶段、旧计划替换、报价消费和未知资金。
- 假文件系统显式区分文件内容与目录项耐久，模拟崩溃后恢复旧目录项和新快照。临时真实文件系统另在十个关键点 SIGKILL 子进程再启动，核对旧计划、候选计划、回执和同键重放。**这些不是实际断电、磁盘固件或电源故障测试。**
- 实际 main 子进程覆盖正常关闭、挂起扫描/财务任务、未关闭 socket、同步保存超时、重复信号、退出码与残留 interval；独立 supervisor 对永久同步阻塞做强杀验证。
- `npm test` 包含全部专项、既有单测、安全、并发、契约、临时 PostgreSQL 17 迁移实验；Redis 测试使用进程内 RESP 假服务，不能声称真实 Redis 集群验收。
- `npm run contract:check`、所有 `.mjs` 语法检查和 CI 凭据扫描；仓库没有独立 Lint 或编译脚本。本轮完整测试为 159 项通过、0 失败、0 跳过；远端 CI 以最终交付记录为准。
- `generate-reservation-fixtures.mjs` 以假身份和临时存储调用实际 handler，生成报价和错误响应并同步 Day；Cloud 测试验证完整固定字段、类型、单位、版本和错误，随机 ID/摘要单独归一化。Day CI 固定 Cloud 提交并比较 fixture 原字节。

## 兼容、迁移和回滚

不新增 SQL migration；快照增加 `storage_protocol=2`、`priceQuotes`、`outboxEvents` 和回执规范化 hash，旧字段不移除，缺少新字段的旧快照仍可加载。旧回执继续按旧 hash 检查；已经被历史版本丢掉的回执无法凭空重建，不能对这部分历史键作永久防重复承诺。

Compose 原先设置的 `DIS_PERSIST_PATH` 未被 main 读取；现在使用 `CLOUD_SNAPSHOT_PATH`，保留运维显式覆盖，默认 `/app/.data/cloud-state.json`。升级前须核对当前进程实际快照路径和卷挂载，维持原路径或连同 intent 完整迁移；不能指向空目录而丢失旧计划。

升级前由运维停止唯一写者并备份**整个快照目录**，包括 `.intent`；本轮没有执行生产备份或迁移。恢复失败时保留现场，不删除 intent、不从较旧备份覆盖未知资金，也不清回执重试。先修复 I/O，再由新版启动恢复协议核验；摘要不符需离线核对候选、旧备份、学校与资金账本。

回滚应用前必须先由新版核验至稳定状态并停止写者，备份最新目录。旧代码不了解 intent 和隔离状态，且会截断回执、丢弃报价/outbox，因此**存在 intent、未知提交、资金未核对或超出旧版回执容量时禁止直接降级写入**；应保留新版持久化层或前向修复。不能恢复旧数据快照以撤销已发生的外部预约或资金操作。

## 提交、恢复与兼容边界

`packages/db` 严格提交使用候选文件 fsync、先持久化提交意图、rename、目录 fsync、全内容摘要与提交单元核验、删除意图再同步目录。发布前失败可安全回滚；发布后故障保持 UNKNOWN，所有后续 HTTP 写入、扫描与财务入口受屏障限制。恢复只在快照与 previous/next 摘要相符、报价消费/plan/job/event/receipt 同一单元且文件和目录同步完成后解除隔离。同 key 才返回原回执，不同 payload 拒绝；未知不换 key。

旧客户端可走 expected_price 的兼容路径，旧整数 price_version 在 Day 端归一化；坏报价、未知单位/错误不得降级。退款旧入口现在返回 202 的双人审批申请，旧后台不得把它解释为已退款。旧未知退款仅原事件键只读核验，不合成审批，不自动再扣退款。

新快照有 protocol v2、idempotencyRecords、priceQuotes、refundRequests、outboxEvents；旧程序可能忽略并在下一次保存时丢弃这些字段。禁止将旧程序直接接到升级后仍有新流量的快照上运行。Room 迁移与 Android 回滚另见 Day 验收报告。

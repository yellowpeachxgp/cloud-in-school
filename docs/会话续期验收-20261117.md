# 会话续期修复与验收

客户端旧版保存的明文云令牌在升级后被新密封格式直接拒绝，原账号绑定仍显示，续期入口却拿不到令牌。本轮客户端兼容修复及真实 Android 验证另见 Day 对应 PR；本文记录 Cloud 会话边界。

Cloud 的登录签发、刷新轮换、退出及重放撤销原先仅安排 200ms 延迟保存，响应成功早于快照落盘。新增真实临时文件回归首先复现登录后立即重建无会话、续期后重建新令牌返回 401 等问题。现于响应前严格提交，新旧轮换状态在同一快照内；确定未提交时恢复原令牌，rename 后失败保留未知及写入围栏，不返回确定成功。会话撤销也在响应前耐久保存，不放宽重放检测。

专项覆盖首次签发、实际刷新 HTTP handler、轮换后重建与旧令牌重放、rename 前失败、rename 后目录同步失败和恢复、退出后重建。另以真实 main 启动隔离子进程，经 HTTP 收到成功后 SIGKILL 并重启三次，确认新令牌可继续续期、重放撤销持续生效。子进程使用独立临时快照与假身份，不调用学校或资金；这些实验不等于真实断电。

本机存在其他项目并发构建，原无限制并行的完整套件出现关闭计时抖动。将测试文件并行数限制为 4，正常关闭单元用例预算与实际 main 的正常用例统一为 4 秒；故障场景仍以 150ms 校验超时。子进程测试的外部关闭 watchdog 改从收到就绪消息后开始计时，不再把启动时间计入关闭预算，整体测试超时保留启动余量。未跳过用例或删除超时断言。

未改变 HTTP 会话响应、Cookie、令牌格式、快照 schema、用户授权、预约或资金规则。部署需保存原会话签名/KMS/SSO 配置、先停旧 API 写者、备份当前快照，再启动新 API；不能恢复旧快照覆盖新预约/资金。旧客户端仍兼容。没有多副本租约或 fencing，仍只允许一个 API 快照写者。

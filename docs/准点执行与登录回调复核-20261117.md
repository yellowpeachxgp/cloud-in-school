# 准点执行与登录回调复核

用户已确认 v0.20.23 手机提交正常。本轮只读核验线上新计划、父任务、三段定时事件和耐久回执，确认上海时区 06:30/06:55/07:00 对应正确 UTC 时刻；任务仍 ARMED，尚未派发。手机提交已更新学校托管凭据，覆盖目标执行日期；没有替用户重复绑定、创建计划、手动执行或操作真实资金。

隔离演练使用相同日期、区域、候选顺序和用座时段，但全部账号、密码、存储、学校响应及资金均为假数据。通过实际 HTTP handler 创建父计划、幂等重试、实际 scanDueScheduleEvents、KMS 续期和学校适配器；推进注入时钟，经历 PRECHECK、FINAL_CHECK、FIRE，重建存储及重复扫描。分别验证正常确认、提交响应未知后只读回查、真实学校适配器的请求构造，以及执行瞬间 Cookie/Token 失效后的密码续期。

新增冷查询场景复现了真实业务漏洞：学校尚未开放导致不能预热，正式执行查询时若登录态失效，原代码即使续期成功，也会因没有“占用/未开放”标记而 break，未再查询、直接报告失败。现只在已确定认证拒绝且续期成功后，继续原有有限轮次、相同日期和候选顺序；不扩大候选范围，不延长执行窗口，不重发未知写入。修复前该完整场景失败（有效提交次数为 0），修复后成功，所有场景仅发出一次有效假学校预约、权威确认后才执行一次沙箱记账。没有修改学校规则或调度器接口。

网页登录补充：失效/重复回调对 JSON 客户端仍返回原认证错误；浏览器若已有独立有效 Cookie，回到工作台，不重新兑换票据或创建会话；无会话则显示中文重新登录入口。所有响应禁止缓存和发送来源引用；存储未知依然返回 503，不能伪装成功。网页座位查询不再吞掉学校授权过期错误，初始绑定卡片如实显示过期；过期/未知状态不冒充空闲，日期切换拒绝晚到结果，刷新保留有效选择。

验证：全部 198 项 Node 测试无失败、无跳过，97 个 API 和 5 份 JSON Schema 契约通过，模块语法检查通过。对应 CI、合并提交和部署核验以最终交付记录为准。真实学校账号只读验证在此前已完成，真实预约结果只能等用户已安排的任务到点，由学校权威回查确认；这些模拟实验不等于已实际抢中、真实断电测试或多副本安全。

兼容与回滚：不改快照协议、Room、幂等键、资金状态或客户端 JSON 契约。客户端继续使用 v0.20.23，无需为服务端修复再次发布手机二进制。部署前停旧写者、备份包含新计划的当前快照和原密钥配置，再启新 API；回滚仅退代码，不用旧快照覆盖新计划，不自动重放未知预约或资金操作。仍为单写者，不宣称多副本安全。
